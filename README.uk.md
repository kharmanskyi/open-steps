# Open Steps

*Короткий переклад [англійського README](README.md). Останнє оновлення: 30 вересня 2026 року. Заміри, будова пака і нотатки для контриб'юторів є лише в англійській версії. Знайшли неточність? Виправте через pull request.*

**Навички, які тримають розробку відкритою для того, хто нею керує: сесії, рішення, наступні кроки, загальна картина, і все простими словами.**

Навички для ШІ-агентів, які говорять простою мовою: Claude Code, Codex, Cursor і Gemini CLI.

Автор: [Pavlo Kharmanskyi](https://github.com/kharmanskyi).

## Навіщо це

Я не інженер. Двадцять років я роблю продукти з боку продукту, сьогодні в моїй компанії понад 50 розробників. Паралельно я почав робити продукт сам, з агентом і без інженерів. Майже одразу наштовхнувся на стіну. Агент добре працює, а потім розповідає про зроблене хешами комітів і жаргоном, і я не можу зрозуміти, закінчили ми чи ні. Сама робота при цьому зроблена нормально. Просто агента ніхто не вчив говорити з людиною, яка не читає код.

Цей пак учить. Він не пише код замість агента і не перевіряє код за нього. Він змінює те, що агент каже вам у кількох важливих моментах, і вимагає доказів там, де раніше вистачало слова «готово».

## Що роблять навички

| Навичка | Що робить | Коли спрацьовує |
|---|---|---|
| `os-done-or-not` | Звіт на один екран із вердиктом: зроблено чи ні, що потрібно від вас, чи з'явилися нові борги, чи можна закривати. У кожного «так» є доказ | Робота закінчена, або ви питаєте, як усе пройшло |
| `os-step-by-step` | Покрокова інструкція без жаргону, яку може виконати людина без технічної підготовки. Спочатку агент має спробувати все сам і попросити лише те, що справді потрібно від вас | Агенту треба, щоб ви щось запустили, вставили, натиснули, схвалили чи перевірили |
| `os-ask-simple` | Питання простими словами, у що воно обійдеться потім, і одна прямо названа рекомендація | В агента до вас питання або варіанти |
| `os-what-could-go-wrong` | Вважає, що рішення вже провалилося, і шукає чому. Це робить окремий свіжий агент, який до рішення не причетний. Наприкінці один вердикт | Ось-ось ухвалять рішення, яке важко скасувати: договір, покупка, міграція, запуск |
| `os-whats-next` | Спочатку вливає в основну гілку (merge) те, що перевірено й готове, потім радить наступне завдання і пояснює чому простими словами | Ви питаєте, що лишилося або що робити далі |
| `os-check-work` | Не вірить звіту іншої сесії на слово. Звіряє кожне твердження з тим, що сталося насправді, і каже, що з цим робити | Інша сесія каже, що закінчила |
| `os-say-simple` | Переказує будь-який текст простими словами, не втрачаючи фактів і поганих новин. Назвіть число і отримаєте рівно стільки пунктів | Будь-який текст читається як інженерний: звіт, коментар, помилка, відповідь самого агента |
| `os-big-picture` | Веде один файл `BIG-PICTURE.md`: що це за продукт, кожна функція і як далеко вона дійшла, що давно ніхто не чіпав, що в черзі. Якщо у вас уже є трекер задач, пропонує відкрити чергу як задачі в ньому | Ви питаєте, де ми зараз, або щойно записано звіт сесії |

Навички просять агента відповідати тією мовою, якою ви з ним говорите. Код, назви файлів і команди лишаються англійськими.

## Встановлення

**Важливо знати до встановлення: пак сам вливає pull request в основну гілку (merge), якщо в нього зелені перевірки і схвалене рев'ю.** Перед цим агент перевіряє його ще раз. У Claude Code вливання відбувається без запиту дозволу. У Codex, Cursor і Gemini CLI команда вливання проходить через налаштування дозволів самого інструмента, так сказано в їхній документації. Вливання зупиняють дві речі: твердження, яке не пройшло перевірку, або позначка в задачі, що вливати лише за командою. Якщо хочете, щоб вливання було лише за командою, напишіть це у файлі постійних інструкцій: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md` або `AGENTS.md` проєкту в Cursor.

Пак встановлюється в Claude Code, Codex, Cursor і Gemini CLI. У Claude Code плагін підключає навички й обидва хуки однією командою. У Codex, Cursor і Gemini CLI навички встановлює одна команда копіювання, а хуки налаштовуються вручну в кожному інструменті. Що запускали на кожному інструменті, а що взято з його документації, показує [таблиця в англійському README](README.md#what-was-run-on-each-tool).

### Спочатку, для будь-якого інструмента

Завантажте репозиторій:

```bash
git clone https://github.com/kharmanskyi/open-steps.git
```

Усі команди нижче запускаються з папки, куди ви його завантажили, тієї, де тепер лежить `open-steps/`, а не зсередини.

У будь-якому з чотирьох інструментів одну річ варто додати руками: блок правил у файл, який інструмент читає як постійні інструкції. Навички агент обирає сам. Хуки йому нагадують, а в Claude Code цей блок перетворює нагадування на правило. Куди класти блок, сказано нижче для кожного інструмента.

Звіти зберігаються поза вашими репозиторіями, у `~/.claude/open-steps/reports/<project>/`, тому не потрапляють у коміти.

### Claude Code

Встановіть пак як плагін:

```bash
claude plugin marketplace add ./open-steps && claude plugin install open-steps@open-steps
```

Готово: навички й обидва хуки підключено. Подивитися, що вийшло:

```bash
claude plugin details open-steps
```

Блок правил іде у ваш `~/.claude/CLAUDE.md`, там він переживає довгі розмови. Одна команда, її безпечно повторювати:

```bash
grep -q 'os-done-or-not' ~/.claude/CLAUDE.md 2>/dev/null || cat open-steps/docs/routing-block.md >> ~/.claude/CLAUDE.md
```

Пізніше перевірити все встановлення, а не лише плагін: команда `/open-steps:os-install-check` у Claude Code. Вона каже, що підключено, що ні, і пише «не перевірено» там, де не змогла подивитися.

### Codex CLI, Cursor CLI і Gemini CLI

Ці три інструменти читають навички з `~/.agents/skills/`. Одна команда встановлює навички для всіх трьох:

```bash
mkdir -p ~/.agents/skills && cp -R open-steps/skills/os-* ~/.agents/skills/
```

Блок правил іде у файл, який інструмент читає як постійні інструкції:

| Інструмент | Куди йде блок |
|---|---|
| Codex | `~/.codex/AGENTS.md` |
| Cursor | `AGENTS.md` у корені проєкту |
| Gemini CLI | `~/.gemini/GEMINI.md` |

Команда для кожного файлу, її безпечно повторювати, є в [docs/other-agents.md](docs/other-agents.md#the-routing-block) (англійською). Там само налаштування хуків: у кожному інструменті воно своє і робиться вручну.

Перевірити встановлення: `bash open-steps/doctor.sh`. Він дивиться папки навичок, блок правил і налаштування хуків кожного знайденого інструмента й пише «не перевірено» там, де не зміг подивитися. Під якою подією стоїть кожен хук, він поки не перевіряє.

## Оновлення і видалення

**Claude Code.** Оновити: `git pull` всередині `open-steps/`, потім `claude plugin update open-steps@open-steps`. Потрібні обидві половини: плагін оновлюється з вашої папки, а не з GitHub, і файли потрапляють у встановлену копію лише коли змінився номер версії. Видалити: `claude plugin uninstall open-steps`, потім прибрати блок із `CLAUDE.md`.

**Codex CLI, Cursor CLI і Gemini CLI.** Оновити: `git pull` всередині `open-steps/`, потім знову команда копіювання. Це копія, тому встановлені навички не змінюються, доки ви її не повторите. Видалити (ці кроки ще не запускали): стерти папки `os-*` з `~/.agents/skills/`, прибрати блок із файлу інструкцій інструмента і два записи хуків із його файлу налаштувань (`~/.codex/config.toml`, `~/.cursor/hooks.json` або `~/.gemini/settings.json`).
