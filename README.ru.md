# Open Steps

*Короткий перевод [английского README](README.md). Последнее обновление: 30 сентября 2026 года. Замеры, устройство пака и заметки для контрибьюторов есть только в английской версии. Если нашли неточность, поправьте через pull request.*

**Навыки, которые держат разработку открытой для того, кто ею управляет: сессии, решения, следующие шаги, общая картина, и всё простыми словами.**

Навыки для ИИ-агентов, которые говорят простым языком: Claude Code, Codex, Cursor и Gemini CLI.

Автор: [Pavlo Kharmanskyi](https://github.com/kharmanskyi).

## Зачем это

Я не инженер. Двадцать лет я делаю продукты со стороны продукта, сейчас в моей компании больше 50 разработчиков. Параллельно я начал делать продукт сам, с агентом и без инженеров. Почти сразу упёрся в стену. Агент хорошо работает, а потом рассказывает о сделанном хешами коммитов и жаргоном, и я не могу понять, закончили мы или нет. Сама работа при этом сделана нормально. Просто агента никто не учил говорить с человеком, который не читает код.

Этот пак учит. Он не пишет код за агента и не проверяет код вместо него. Он меняет то, что агент говорит вам в нескольких важных моментах, и требует доказательств там, где раньше хватало слова «готово».

## Что делают навыки

| Навык | Что делает | Когда срабатывает |
|---|---|---|
| `os-done-or-not` | Отчёт на один экран с вердиктом: сделано или нет, что нужно от вас, появились ли новые долги, можно ли закрывать. У каждого «да» есть доказательство | Работа закончена, или вы спрашиваете, как всё прошло |
| `os-step-by-step` | Пошаговая инструкция без жаргона, которую может выполнить человек без технической подготовки. Сначала агент обязан попробовать всё сам и попросить только то, что правда нужно от вас | Агенту нужно, чтобы вы что-то запустили, вставили, нажали, одобрили или проверили |
| `os-ask-simple` | Вопрос простыми словами, во что он обойдётся потом, и одна рекомендация, названная прямо | У агента к вам вопрос или варианты |
| `os-what-could-go-wrong` | Считает, что решение уже провалилось, и ищет почему. Этим занимается отдельный свежий агент, который к решению не причастен. В конце один вердикт | Вот-вот примут решение, которое трудно отменить: договор, покупка, миграция, запуск |
| `os-whats-next` | Сначала вливает в основную ветку (merge) то, что проверено и готово, потом рекомендует следующую задачу и объясняет почему простыми словами | Вы спрашиваете, что осталось или что делать дальше |
| `os-check-work` | Не верит отчёту другой сессии на слово. Сверяет каждое заявление с тем, что произошло на самом деле, и говорит, что с этим делать | Другая сессия говорит, что закончила |
| `os-say-simple` | Пересказывает любой текст простыми словами, не теряя фактов и плохих новостей. Назовите число и получите ровно столько пунктов | Любой текст читается как инженерный: отчёт, комментарий, ошибка, ответ самого агента |
| `os-big-picture` | Ведёт один файл `BIG-PICTURE.md`: что это за продукт, каждая функция и как далеко она дошла, что давно никто не трогал, что в очереди. Если у вас уже есть трекер задач, предлагает открыть очередь как задачи в нём | Вы спрашиваете, где мы сейчас, или только что записан отчёт сессии |

Навыки просят агента отвечать на том языке, на котором вы с ним говорите. Код, названия файлов и команды остаются на английском.

## Установка

**Важно знать до установки: пак сам вливает pull request в основную ветку (merge), если у него зелёные проверки и одобренное ревью.** Перед этим агент проверяет его ещё раз. В Claude Code вливание проходит без запроса разрешения. В Codex, Cursor и Gemini CLI команда вливания проходит через настройки разрешений самого инструмента, так сказано в их документации. Вливание останавливают две вещи: заявление, которое не прошло проверку, или пометка в задаче, что вливать только по команде. Если хотите, чтобы вливание было только по команде, напишите это в файле постоянных инструкций: `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.gemini/GEMINI.md` или `AGENTS.md` проекта в Cursor.

Пак ставится в Claude Code, Codex, Cursor и Gemini CLI. В Claude Code плагин подключает навыки и оба хука одной командой. В Codex, Cursor и Gemini CLI навыки ставит одна команда копирования, а хуки настраиваются вручную в каждом инструменте. Что запускали на каждом инструменте, а что взято из его документации, показывает [таблица в английском README](README.md#what-was-run-on-each-tool).

### Сначала, для любого инструмента

Скачайте репозиторий:

```bash
git clone https://github.com/kharmanskyi/open-steps.git
```

Все команды ниже запускаются из папки, в которую вы его скачали, той, где теперь лежит `open-steps/`, а не изнутри неё.

В любом из четырёх инструментов одну вещь стоит добавить руками: блок правил в файл, который инструмент читает как постоянные инструкции. Навыки агент выбирает сам. Хуки ему напоминают, а в Claude Code этот блок превращает напоминание в правило. Куда класть блок, сказано ниже для каждого инструмента.

Отчёты сохраняются вне ваших репозиториев, в `~/.claude/open-steps/reports/<project>/`, поэтому не попадают в коммиты.

### Claude Code

Установите пак как плагин:

```bash
claude plugin marketplace add ./open-steps && claude plugin install open-steps@open-steps
```

Готово: навыки и оба хука подключены. Посмотреть, что получилось:

```bash
claude plugin details open-steps
```

Блок правил идёт в ваш `~/.claude/CLAUDE.md`, там он переживает длинные разговоры. Одна команда, её безопасно повторять:

```bash
grep -q 'os-done-or-not' ~/.claude/CLAUDE.md 2>/dev/null || cat open-steps/docs/routing-block.md >> ~/.claude/CLAUDE.md
```

Позже проверить всю установку, а не только плагин: команда `/open-steps:os-install-check` в Claude Code. Она говорит, что подключено, что нет, и пишет «не проверено» там, где не смогла посмотреть.

### Codex CLI, Cursor CLI и Gemini CLI

Эти три инструмента читают навыки из `~/.agents/skills/`. Одна команда ставит навыки для всех трёх:

```bash
mkdir -p ~/.agents/skills && cp -R open-steps/skills/os-* ~/.agents/skills/
```

Блок правил идёт в файл, который инструмент читает как постоянные инструкции:

| Инструмент | Куда идёт блок |
|---|---|
| Codex | `~/.codex/AGENTS.md` |
| Cursor | `AGENTS.md` в корне проекта |
| Gemini CLI | `~/.gemini/GEMINI.md` |

Команда для каждого файла, её безопасно повторять, есть в [docs/other-agents.md](docs/other-agents.md#the-routing-block) (по-английски). Там же настройка хуков: в каждом инструменте она своя и делается вручную.

Проверить установку: `bash open-steps/doctor.sh`. Он смотрит папки навыков, блок правил и настройки хуков каждого найденного инструмента и пишет «не проверено» там, где не смог посмотреть. Под каким событием стоит каждый хук, он пока не проверяет.

## Обновление и удаление

**Claude Code.** Обновить: `git pull` внутри `open-steps/`, затем `claude plugin update open-steps@open-steps`. Нужны обе половины: плагин обновляется из вашей папки, а не с GitHub, и файлы попадают в установленную копию только когда сменился номер версии. Удалить: `claude plugin uninstall open-steps`, затем убрать блок из `CLAUDE.md`.

**Codex CLI, Cursor CLI и Gemini CLI.** Обновить: `git pull` внутри `open-steps/`, затем снова команда копирования. Это копия, поэтому установленные навыки не меняются, пока вы её не повторите. Удалить (эти шаги ещё не запускали): стереть папки `os-*` из `~/.agents/skills/`, убрать блок из файла инструкций инструмента и две записи хуков из его файла настроек (`~/.codex/config.toml`, `~/.cursor/hooks.json` или `~/.gemini/settings.json`).
